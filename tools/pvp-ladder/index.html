数字の出どころ

挑戦できる相手の範囲。ブルアカ攻略 Wiki「戦術対抗戦」の記述をそのまま使っています。「自分の順位×0.7〜0.8(上段)、0.8〜0.9(中段)、0.9〜0.95(下段)となっており、同じ相手は同時には表示されない」「13位からは範囲が縮小されてしまうためか対戦相手の順位は固定化され、11位～13位は自分の順位から2～4、10～4位は自分の順位から1～3の範囲となる」「例えば11位から10位へは絶対に挑めない。」「※12位以降は対戦相手の順位が固定化されるため、4位から1位に挑戦が可能」。 このうち 13 位より下の倍率は、ba-data の Excel/ConstArenaExcelTable.json にも RelativeOpponentRankStart: [2000, 1000, 500] ／ RelativeOpponentRankEnd: [3000, 2000, 1000]（自分の順位に対する 10000 分率。引き算すると ×0.7〜0.8 ／ ×0.8〜0.9 ／ ×0.9〜0.95 の 3 枠）として入っていて、Wiki の記述と一致します。13 位以下の固定範囲（−2〜−4 と −1〜−3）はゲームデータに見つからず、Wiki の記述だけが根拠です。2026-08-31 に Excel/ConstArenaExcelTable.json の全フィールド（2026-09-24 に数え直して 33 列）と、DB/ にある Arena 系 6 表（ArenaSeasonExcelTable / ArenaLevelSectionExcelTable / ArenaMapExcelTable / ArenaNPCExcelTable / ArenaRewardExcelTable / ArenaSeasonCloseRewardExcelTable）を見直しましたが、順位変動に関わる列はありませんでした。ほかの攻略サイト（game8・神ゲー攻略・ゲーム乱舞・Gamerch）にもこの固定範囲の記載は見つかっていません。

15001 位から 1 位までは 24 段・23 回。 15001 → 10500 → 7350 → 5145 → 3601 → 2520 → 1764 → 1234 → 863 → 604 → 422 → 295 → 206 → 144 → 100 → 70 → 49 → 34 → 23 → 16 → 11 → 7 → 4 → 1。同じ Wiki にも「15001位から…最低23回対戦する必要がある」として同じ並びが載っています。 開始順位の 15001 は、同じ Wiki の「シーズン開始直後は人間プレイヤーは全員15001位からスタートし、それ以外はNPCで埋まっている」が根拠です。個人ブログ（詩音ブログ）にも「15001位→10500位→7350位→5145位→3601位」と同じ並びが載っていて食い違いません。データ側で確かめられるのは、1 グループの上限が 15000 人（DB/ArenaSeasonExcelTable.json の SeasonGroupLimit: 15000。全 11 シーズンとも同じ値）と、報酬表の最下段が 15000 位まで、というところまでです（15001 ＝ 15000 人の次、と読めますが、データにその数字そのものはありません）。

負けたときの下がり方（およそ 1.4 倍）。同じ Wiki の「挑戦できる順位の上限は、自分の順位×0.7(少数点以下は切捨)が目安。逆に、一度に下がる順位の上限は自分の順位×1.4辺りとなる」が根拠です。クライアント側のデータには順位変動に関わる値が見つからず、ほかのサイトにもこの数字は見つかっていません。ページでは「およそ」を付けたままにしています。

挑戦チケット。1 日 5 枚は DB/CurrencyExcelTable.json の ArenaTicket（DailyRefillAmount: 5、持てる上限も 5 枚）、買い足しは DB/GoodsExcelTable.json の Id 40 が青輝石 60 個でチケット 5 枚（ConsumeParcelAmount: [60] → ParcelAmount: [5]）、1 戦 1 枚は Excel/ConstArenaExcelTable.json の TicketCost: 1 です。

日別報酬。順位帯ごとの青輝石と戦術対抗戦コインの枚数は、ba-data の DB/ArenaRewardExcelTable.json（ArenaRewardType: "Daily" の 11 行）そのものです。リセットが毎日 14 時（Excel/ConstArenaExcelTable.json の DailyRewardResetTime）、防衛で勝つと 1 勝 3 枚（DB/ArenaRewardExcelTable.json の DefenseVictory）・1 日 10 回まで（Excel/ConstArenaExcelTable.json の DefenseVictoryRewardMaxCount）というのも同じデータです。 1 位 45＋125 ／ 2 位 40＋120 ／ 3〜10 位 35＋110 ／ 11〜100 位 30＋100 ／ 101〜200 位 25＋90 ／ 201〜500 位 20＋80 ／ 501〜1000 位 18＋70 ／ 1001〜2000 位 16＋60 ／ 2001〜4000 位 14＋50 ／ 4001〜8000 位 12＋40 ／ 8001〜15000 位 10＋30（左が青輝石、右が戦術対抗戦コイン）。有志ツール「戦術対抗戦石割収支集計ツール」の実装に載っていた値とも同じでした。

参照している側について。ba-data には Excel/ と DB/ の 2 系統があり、Excel/ は表ごとに古い時点で止まっています。このページの数字は更新が続いている DB/ から scripts/build-tool-data.py が毎日取り直しています（2026-09-26 に 9/23 の更新・v1.73.459696 で突き合わせ、日別報酬・防衛勝利・ショップの品・チケットとも前と同じでした）。ConstArenaExcelTable だけは DB/ に存在しないため Excel/ 側（最終更新 2026-04-01・v1.67.412528）を見ています。

出典 — ブルアカ攻略 Wiki「戦術対抗戦」、ゲームエイト「戦術コインのおすすめ交換先と入手方法」、 kur-3dcg/Tactical-Battle-Stone-Accounting。

数字の出どころ

枚数はゲームのデータそのものです。ba-data の DB/ArenaRewardExcelTable.json に、順位帯ごとの日別報酬が 11 行あります。11 〜 100 位なら RewardParcelAmount: [30, 100]（青輝石 30 と戦術対抗戦コイン 100）、というふうに。下に並べたのがその 11 行の中身で、ページの選択肢と 1 行ずつ突き合わせてあります。

1 位 45＋125 ／ 2 位 40＋120 ／ 3〜10 位 35＋110 ／ 11〜100 位 30＋100 ／ 101〜200 位 25＋90 ／ 201〜500 位 20＋80 ／ 501〜1000 位 18＋70 ／ 1001〜2000 位 16＋60 ／ 2001〜4000 位 14＋50 ／ 4001〜8000 位 12＋40 ／ 8001〜15000 位 10＋30（左が青輝石、右が戦術対抗戦コイン）。

防衛で勝ったぶんと、リセットの時刻も同じデータから取りました。同じ表の DefenseVictory が ArenaCoin 3 枚で、Excel/ConstArenaExcelTable.json の DefenseVictoryRewardMaxCount: 10 が 1 日の上限、DailyRewardResetTime: 14:00:00 がリセットの時刻です。日別報酬は 1 日 1 回で、14 時のリセット時点の順位で決まります。その時間に 11 〜 100 位に居れば、その日は 100 枚です。

交換所のレートもデータそのものです。DB/ShopInfoExcelTable.json の CategoryType: "Arena" から DB/GoodsExcelTable.json を引きます。AP ドリンク（初級）が Id 3100 で ConsumeParcelAmount: [15]、その中身は DB/ItemExcelTable.json の Id 10000000 が UsingResultAmount: 30（AP30）。中級（Id 3101）が 30 枚で AP60。ショップの更新は Id 106 の 10 枚で、1 日 3 回までは RefreshAbleCount: 3 です。

神名文字は 1 個 50 枚ではなく、1 口 50 枚で 5 個です。DB/GoodsExcelTable.json の Id 3000〜3006 の 7 枠がどれも ConsumeParcelAmount: [50] → ParcelAmount: [5]。 並ぶのはサヤ・フウカ・ウタハ・マシロ・シズコ・ミヤコ・ミユの 7 人ぶんです。2026 年 8 月 30 日まで「1 個 50 枚」として数えていて、支出が 5 倍に出ていました。いまは買う口数を入れてもらう形にしてあります。 7 枠それぞれ DB/ShopRefreshExcelTable.json（CategoryType: "Arena"）の Prob: 50 で抽選されるので、更新のたびに必ず 7 枠とも出るわけではありません。AP ドリンクの 2 枠（Id 3100 / 3101）も同じ Prob: 50 です。このツールは「並んだものは毎回買う」で数えているので、出ない回があるぶん、出ていくコインは多めに出ます。

参照している側について。ba-data には Excel/ と DB/ の 2 系統があり、Excel/ は表ごとに古い時点で止まっています。このページの数字は更新が続いている DB/ から scripts/build-tool-data.py が毎日取り直しています（2026-09-26 に 9/23 の更新・v1.73.459696 で突き合わせ、日別報酬・防衛勝利・ショップの品・チケットとも前と同じでした）。ConstArenaExcelTable だけは DB/ に存在しないため Excel/ 側（最終更新 2026-04-01・v1.67.412528）を見ています。
