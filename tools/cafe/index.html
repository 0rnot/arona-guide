快適度をどう作るか

快適度は家具の合計 ＋ セットボーナス（上限で頭打ち）です。

同じセットをその段でそこまでの合計1 個あたり

段のボーナスは足し上がります。同時に 3 セットまで効くので、上限は ＋4,500 です。

ランクごとの一覧

クレジットと AP は、快適度上限まで埋めたときの 1 時間あたりです。

数字の出どころ

時給の式はゲームのデータそのままです。それが正しいことを、データの中だけで確かめられました。

  • 1 時間あたりの生産量は (ParcelProductionCoefficient × 快適度 + ParcelProductionCorrectionValue) / 10000。 Excel/CafeProductionExcelTable.json の 30 行から引いています。 10000 で割り忘れるとランク 1 で 1,875 万クレジット/時になります。
  • 10000 で割るのが正しいことの裏取り。快適度を各ランクの ComfortMax に置くと、ParcelStorageMax ÷ 時給 が クレジットの 20 行すべてで 24.000（23.998〜24.000）になります。 倉庫がちょうど 24 時間ぶんという形で、 Excel/ConstCommonExcelTable.json の CafeAutoChargePeriodInMsc = 3600000（1 時間）とも合います。 1 行でも 0.01 以上ずれたら、データを作る側で止まります。
  • AP は 24 時間ぶんちょうどではありません。倉庫の上限が 90 / 150 / 220 … と丸められていて、23.45〜24.02 に散ります。 この画面では AP の倉庫に「24 時間ぶん」と書いていません
  • 外の表とも突き合わせました。 ブルアカ攻略wiki（Gamerch）の 「快適度による収入表」と比べると、1 号店のランク 6〜10 はクレジットが 5 行とも一致 （15833.1 / 18750.8 / 21250.65 / 24167 / 27083.6。こちらは 15,833.15 と 2 桁目まで出しています）。 AP も 19.49 / 22.32 / 25.15 / 27.97 / 30.8 と並んでいて、 こちらの 19.49 / 22.32 / 25.15 / 27.98 / 30.81 と末尾の丸め方が違うだけです。 2 号店はランク 1・2・4〜8 の 7 行が小数点まで完全に一致しました （1250.05 / 2291.85 / 5000 / 6771.05 / 7916.65 / 9375.6 / 10625.55）。 ランク 3 だけ向こうが 3541 と桁を落としていて、こちらは 3,541.85 です。 1 号店のランク 2〜5 だけ向こうが「倉庫 ÷ 24」の概数を載せているぶんずれます
  • 快適度の上限・招待人数・タグ数は Excel/CafeRankExcelTable.json。 1000 から 500 きざみで 5500 までで、これが並んでいない場合はデータを作る側で止まります。 上限 5500 は ゲームエイトの 「1号店2号店ともに5500が最大値」と一致します
  • ランクアップの費用は CafeRankExcelTable.RecipeId → Excel/RecipeExcelTable.json（RecipeType が CafeRankUp）→ Excel/RecipeIngredientExcelTable.json。 ランク N の行に付くレシピは「N から N+1 へ」です。 ランク 10 の行にもレシピがありますが、上限が 10 なので使いません。 1 号店と 2 号店でクレジットが同額であることを確かめています
  • セットボーナスは Excel/FurnitureGroupExcelTable.json。 2 / 3 / 5 / 7 個で ＋100 / 200 / 450 / 750（足し上がるので 7 個で合計 ＋1,500。 データは段ごとの数しか持たないので、 神ゲー攻略と ゲームエイトで確かめました）で、 20 セットすべて同じ値でした（1 つでも違えばセットごとに持つ形へ直します）。 同時に効く数は ConstCommonExcelTable.CafeSetGroupApplyCount の —
  • 家具 — 個とセット名は SchaleDB の furniture。ba-data の FurnitureGroupExcelTable は 20 セットしか無く、SchaleDB は 25 セット持っています。 足りない 5 セットは名前だけ SchaleDB から借りていて、 ボーナスの段はそちらでは裏が取れていません（一覧に印を付けています）

出していないもの。家具をカフェの床に詰める配置は作っていません。 家具の Size はデータにありますが、床の広さと置ける形がデータのどこにも無いので、 「マスあたりの快適度」までにしています。 招待できる生徒の当選確率（CafeVisitWeightBase ほか）も式が分からないので、 CharacterVisitMin 〜 CharacterVisitMax の幅だけを出しています。 CafeRandomVisitMinComfortBonus = 1000 の意味も分かりませんでした。 裏が取れないものは書かないことにしています。
