■ ボスの中身について

スキルの文は SchaleDB の data/jp/raids.min.json にある RaidSkills そのままです。どのスキルがどの難易度で出るかは Raid[].RaidSkillList で、並びは EnemyList（＝難易度）と同じです。難易度が上がると BinahExSkill01 → BinahInsaneExSkill01 → BinahTormentExSkill01 → BinahLunaticExSkill01 のように別のキーの別の文に差し替わるので、こちらで数値を作り直してはいません。日本語の文は向こうで完成しています（2026-08-31 に 345 件ぜんぶを数えて、{0} のような差し込みが 1 件も無いことを確かめました）。通常攻撃だけは RaidSkills に無いので出していません。

<b:ATK> のような表記タグは、data/jp/localization.min.json の BuffName で日本語に置き換えています。頭の文字が種類で、b がバフ（Buff_ATK）、d がデバフ（Debuff_Burn）、c が行動不能（CC_Stunned）、s が特殊状態（Special_Immortal）です。色はその 4 種類にだけ付けています。<up> は上位難易度で強くなった箇所で、太字にしています。「？」と出ている箇所は、SchaleDB のデータに数値が入っていないところです（セトの憤怒・シロ&クロ・KAITEN FX Mk.0 のいくつかのスキル）。こちらでは埋めていません。

パーツ・分身・雑魚は Raid[].EnemyList の 2 体目以降です。1 つの難易度に敵の ID が何個も並んでいて、先頭がボス本体、それ以降がパーツや湧きです（ドラム缶ガニは 9 体、イェソドは 8 体、ケセドとホバークラフトは 7 体）。名前・HP・ランクは data/jp/enemies.min.json の各敵から、ランクの日本語は localization.min.json の EnemyRank から取っています。絵は Icon の値をそのままファイル名にした images/enemy/ の画像です（Icon が空の敵は絵無しで出します）。

フェーズが変わる HP は enemies.min.json の PhaseChange です。129 件ぜんぶを数えて、Trigger が HPUnder しか無いことを確かめました。しきい値は割合ではなく実数で入っているので、パーセントはこちらで最大 HP で割っています。文の言い回しは localization.min.json の RaidChangePhase のものです。

グロッキーゲージの溜まり方は localization.min.json の GroggyCondition です。キーがボスの DevName とそのまま一致します。ここに載っていないボスは、その欄を出していません。ダメージの蓄積で溜まるふつうの方式だと思われますが、データに書いていないことをこちらで書き足すのはやめました。

■ TL の保管庫と検索について

このページに、他人が作った TL は 1 本も入っていません。このサイトは GitHub Pages の静的配信で、サーバーもデータベースもありません。投稿を受け取る仕組みが作れないので、代わりに「自分の TL を自分の端末に貯める帳面」と「よそへ条件ごと飛ばすリンク」の 2 つにしてあります。中身の分からない TL を作って並べることはしません。

保存先は localStorage の arona-tl-vault ひとつです。入っているのは、あなたが貼ったコスト計算機のハッシュと、あなたが選んだボス・難易度・地形・タイム・メモだけ。どこにも送信していません。ブラウザごと・端末ごとに別で、閲覧データを消すと一緒に消えます。書き出した JSON がそのまま中身です。

編成の絵と人数は、貼られたハッシュをその場で読んだ結果です。形は TL のコスト計算機の tl.js にある toHash() / fromHash() と同じで、モード｜編成｜撃つ順番｜開始・上限・ステージ補正 の 4 つを | で区切ったものです。編成は枠の順に , 区切り、空き枠は _、1 枠が 生徒 ID . EX レベル . 通常スキルレベル から始まります。枠はストライカー 6 ＋ スペシャル 4 の固定長で、通常編成は 4＋2、制約解除決戦は 6＋4 までが生きています。ここでもその通りに数えているので、モードを 6 に戻したときに消える枠は人数に入りません。

「いまコスト計算機で開いている TL を取り込む」は、あちらが同じブラウザに置いている arona-cost-timeline を読んで組み直しています。組んだハッシュは、保存する前に必ずこちらの読み取りに通しています。読めなければ保存させません。

保存するときのボス・種類・地形・難易度は、ページ先頭のボス選択から取っています。取り込み欄に同じ選択肢を並べても迷うだけなので、2026-08-30 に一本化しました。URL のハッシュ（#tls=ボス~難易度~地形~生徒~語句）の形は変えていません。他のページから #tls=b4~~Indoor~~ のような形で飛んできたときは、そのボスと地形が選ばれた状態で開きます。

ボス・生徒・難易度の名前は data.js（このツール自身）（window.RAID）から読んでいます。総力戦・大決戦のボス 14 体は bosses、制約解除決戦の 6 体は multi、生徒 — 人は students です。大決戦にも出るボスかどうかは、開催の記録（elim）に載っているかで決めています。難易度の並び（Normal・Hard・VeryHard・Hardcore・Extreme・Insane・Torment・Lunatic）は labels.RaidDifficulty のままで、制約解除決戦の — という区切りは multi の secs にある階層の区間そのものです。このツールは戦闘の計算を一切していません。ここに数字を作る場所はありません。

ボスの絵は tools/img/boss_<パス名>.webp（520×160）です。パス名は data.js の p で、総力戦の 14 体と制約解除決戦の 6 枠、あわせて 20 枚がそろっています。取れなかったときは名前だけのカードにして、そのボスを一覧から落とさない作りです。

よそのサイトへのリンクは、検索の URL を組み立てているだけです。 TLサーチ（きなこもち）の検索フォームは GET で、boss_id / battle_field_id / armor_id / difficulty という項目を持っています。ボスと地形と装甲の番号は、先方のフォームの <option value> をそのまま写したものです（2026-08-30 に実物で確認。battle_field_id は 市街地 1・屋外 2・屋内 3）。先方が番号を振り直せば、このリンクは外れます。難易度は先方が「階層の区間」で持っているため、制約解除決戦のときだけ渡しています。

飛び先 — TLサーチ（きなこもち）、 BlueArchive Tools の TL 検索、 YouTube、 X。 いずれも当サイトとは関係のない外部サイトです。中身の正しさや掲載の可否は、それぞれの運営者に帰属します。

■ 相性と、連れて行く生徒について

属性の倍率は SchaleDB の data/config.json にある TypeEffectiveness そのままです。 10000 が等倍なので、20000 なら ×2.0、5000 なら ×0.5 です。ここは推測していません。

ボスの地形・装甲・攻撃属性は data/jp/raids.min.json から。 BulletTypeInsane という別の攻撃属性が入っているので、Insane 以上ではそちらに切り替えています。大決戦の装甲の組み合わせは RaidSeasons[].EliminateSeasons の実績から拾っています。

生徒の地形適性は 0〜5 の数値です（ゲーム内の D / C / B / A / S / SS）。固有武器の AdaptationType と AdaptationValue を足したものが、武器ありの値で、並び順にはこちらを使っています。

順位は付けていません。実際の火力はレベル・装備・スキル・編成で変わるもので、ここが出せるのは「属性が通るか」「その地形で当たるか」までです。
