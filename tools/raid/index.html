数字の出どころ

■ ボスの中身について

スキルの文は SchaleDB の data/jp/raids.min.json にある RaidSkills そのままです。どのスキルがどの難易度で出るかは Raid[].RaidSkillList で、並びは EnemyList（＝難易度）と同じです。難易度が上がると BinahExSkill01 → BinahInsaneExSkill01 → BinahTormentExSkill01 → BinahLunaticExSkill01 のように別のキーの別の文に差し替わるので、こちらで数値を作り直してはいません。日本語の文は向こうで完成しています（2026-08-31 に 345 件ぜんぶを数えて、{0} のような差し込みが 1 件も無いことを確かめました）。通常攻撃だけは RaidSkills に無いので出していません。

<b:ATK> のような表記タグは、data/jp/localization.min.json の BuffName で日本語に置き換えています。頭の文字が種類で、b がバフ（Buff_ATK）、d がデバフ（Debuff_Burn）、c が行動不能（CC_Stunned）、s が特殊状態（Special_Immortal）です。色はその 4 種類にだけ付けています。<up> は上位難易度で強くなった箇所で、太字にしています。「？」と出ている箇所は、SchaleDB のデータに数値が入っていないところです（セトの憤怒・シロ&クロ・KAITEN FX Mk.0 のいくつかのスキル）。こちらでは埋めていません。

パーツ・分身・雑魚は Raid[].EnemyList の 2 体目以降です。1 つの難易度に敵の ID が何個も並んでいて、先頭がボス本体、それ以降がパーツや湧きです（ドラム缶ガニは 9 体、イェソドは 8 体、ケセドとホバークラフトは 7 体）。名前・HP・ランクは data/jp/enemies.min.json の各敵から、ランクの日本語は localization.min.json の EnemyRank から取っています。絵は Icon の値をそのままファイル名にした images/enemy/ の画像です（Icon が空の敵は絵無しで出します）。

ランクの日本語は 4 つだけ向こうにあります。EnemyRank に入っているのは Champion（BOSS）・Elite（エリート）・Minion（ミニオン）・Summoned（召喚物）の 4 つで、実際のデータにはあと 3 つ出てきます（Boss 32 体、DestructibleProjectile 32 体、Hallucination 8 体）。この 3 つはこちらで「BOSS」「壊せる弾」「分身」と当てています——向こうに日本語が無いところなので、そこだけは当サイトの言葉です。

フェーズが変わる HP は enemies.min.json の PhaseChange です。129 件ぜんぶを数えて、Trigger が HPUnder しか無いことを確かめました。しきい値は割合ではなく実数で入っているので、パーセントはこちらで最大 HP で割っています。文の言い回しは localization.min.json の RaidChangePhase のものです。

グロッキーゲージの溜まり方は localization.min.json の GroggyCondition です。キーがボスの DevName とそのまま一致します。ここに載っていないボスは、その欄を出していません。ダメージの蓄積で溜まるふつうの方式だと思われますが、データに書いていないことをこちらで書き足すのはやめました。

■ 相性と、連れて行く生徒について

属性の倍率は SchaleDB の data/config.json にある TypeEffectiveness そのままです。 10000 が等倍なので、20000 なら ×2.0、5000 なら ×0.5 です。ここは推測していません。

ボスの地形・装甲・攻撃属性は data/jp/raids.min.json から。 BulletTypeInsane という別の攻撃属性が入っているので、Insane 以上ではそちらに切り替えています。大決戦の装甲の組み合わせは RaidSeasons[].EliminateSeasons の実績から拾っています。

生徒の地形適性は 0〜5 の数値です（ゲーム内の D / C / B / A / S / SS）。固有武器の AdaptationType と AdaptationValue を足したものが、武器ありの値で、並び順にはこちらを使っています。上がるのは ★3（3 凸）からで、上がり幅は 1 段が 248 人、2 段が 27 人です（CharacterWeaponExcelTable の StatType[2] を数えました）。

順位は付けていません。実際の火力はレベル・装備・スキル・編成で変わるもので、ここが出せるのは「属性が通るか」「その地形で当たるか」までです。

数字の出どころ

スコアの式は、ゲームのデータの列そのものです。ba-data の DB/RaidStageExcelTable.json（総力戦 168 行）と DB/EliminateRaidStageExcelTable.json（大決戦 532 行）に、ボスと難易度ごとに 4 つの数が入っています。

  • DefaultClearScore — 倒したときに必ずもらえるぶん
  • HPPercentScore — HP をぜんぶ削ったときのぶん。削りきれなければその割合ぶん
  • PerSecondMinusScore — 1 秒ごとに減るぶん（ただしこの値の 1/10。下に書きました）
  • MaximumScore — 時間ぶんの満額（0 秒で倒したときにもらえる量）

スコア ＝ 倒したぶん ＋ HP ぶん ＋（時間ぶんの満額 − 経過秒 × 1 秒あたり）。時間ぶんは 0 より下には行きません。

式が合っていることは、700 行ぜんぶで確かめました。同じ表に MinimumAcquisitionScore と MaximumAcquisitionScore が入っていて、最低 ＝ DefaultClearScore ＋ HPPercentScore、最高 ＝ 最低 ＋ MaximumScore が 700 行すべてで 1 の狂いもなく一致しました。合わない行が出たらデータを作り直すときに止まります。

PerSecondMinusScore は、そのままでは「1 秒あたり」になりません。1/10 が正しい値です。 この列を割ると MaximumScore ÷ PerSecondMinusScore が 700 行すべてで 360 になりますが、 これを 360 秒と読むと3 分ボスを 2 凸しただけで時間ぶんが 0 になり、誰が撃っても同じ点になってしまいます。実際は違います。

正しくは 1/10 で、時間ぶんが尽きるのは合計 3,600 秒（60 分）です。 きなこもち「総力戦・大決戦スコア計算機」が timeScore = (3600 − clearSeconds) × multiplier という式を使っていて、その multiplier は難易度ごとに 120 / 240 / 480 / 960 / 1440 / 1920 / 2400 / 2880。こちらの PerSecondMinusScore のちょうど 1/10 で、8 段すべて一致します。 あちらの baseScores も DefaultClearScore ＋ HPPercentScore と一致しました——3 分ボスの Torment が 31,076,000、4 分ボスが 31,708,000、4 分 30 秒ボスが 32,502,000。別々に出した数が全部揃ったので、読み違いではありません。

裏付けがもう 1 つあります。アニヲタ Wiki「総力戦（ブルーアーカイブ）」のヒエロニムスの回に 「Torment クリア者の上位 10% からチナトロボーダーとなる 20000 位までのスコア差はわずかに約 4,000」とあります。 1 秒 2,400 点なら 約 1.7 秒ぶんの差で、2 万人が並ぶ幅として無理がありません。 1 秒 24,000 点だと 0.17 秒になってしまい、さすがにあり得ません。

だから「2 凸」以上が意味を持ちます。時間ぶんは部隊をまたいだ合計の戦闘時間で減るので、 倒しきれずに時間切れになった回のぶんも足されます。このツールは凸ごとに時間を入れる形にして、倒しきれなかった回は制限時間そのものを初期値にしています。 最後の 1 回だけは「経過」でも「残り」でも入れられます（残り ＝ 制限時間 − 経過）。

地形と装甲はスコアに関係しません。大決戦の行は「ボス_地形_装甲」という名前で 532 行ありますが、同じボス・同じ難易度なら中身が 1 種類しかありませんでした。総力戦にも Binah_Street のような地形つきの行がありますが、そちらも値は同じです。なので 194 行に畳んで持っています。

ボスの日本語名は SchaleDB から引いています。ゲームのデータ側は Binah のような開発名しか持っていません。表によって大文字小文字が揃っていない（ShiroKuro と Shirokuro）ので小文字にして引き、大決戦だけ別名になっている 2 つ（Kaitenger ＝ KAITEN FX Mk.0、HoverCraft ＝ ホバークラフト）は対応表を持っています。

倒しきれなかったときは、クリアぶんと時間ぶんが入りません。HP を削った割合ぶんだけになります。この扱いはデータに明記されていないので、MinimumAcquisitionScore が「クリアしたときの最低」であることからの読み取りです。

出典 — electricgoat/ba-data（スコアの列）、SchaleDB（ボスの名前と絵）、きなこもち「総力戦・大決戦スコア計算機」（1 秒あたりの減点と 3,600 秒）、アニヲタ Wiki（順位差の実例）。取得は —。

数字の出どころ

開催の日付・ボス・地形は、ゲームのデータそのままです。 raids.min.json の RaidSeasons にある Seasons（総力戦）と EliminateSeasons（大決戦）を、 Start / End（どちらも UNIX 秒）で並べています。時刻はすべて日本時間で出しています。見ている端末の時計に合わせると、海外から見たときに日付がずれるためです。

RaidSeasons はサーバーごとに 3 本入っていて、先頭が日本です。先頭の最後のシーズンが日本の開催日と合うことを確かめて使っています。

大決戦の「Torment に挑戦できる防御タイプ」は OpenDifficulty です。防御タイプごとに、その回で開く難易度の番号が入っています。番号は Normal・Hard・VeryHard・Hardcore・Extreme・Insane・Torment・Lunatic の順で、 6 なら Torment まで、5 なら Insane までです。

「これからの開催」は見積もりではありません。ゲームのデータの期間表から、そのまま出しています。開催済みのぶんは SchaleDB の raids.min.json、これからのぶんは ba-data の期間表という二本立てです。運営の都合でずれることはあるので、最終的な告知は公式 X の「総力戦＆大決戦スケジュール」と「予告」で出ます。期間表が取れなかったときだけ、直近 6 回の間隔から出した見積もりに戻ります。

ボスの装甲と攻撃属性は Raid の ArmorType / BulletType / BulletTypeInsane です。 Insane 以上では攻撃属性が変わるボスがいるので、両方を出しています。相性の詳細は「ボス情報」の区画にあります。
