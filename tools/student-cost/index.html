数字の出どころ

素材とクレジットは、ゲームのレシピをそのまま読んでいます。レシピの Id は 生徒 Id × 1000 ＋ 枠 × 100 ＋ 段で並んでいて、枠 0 が星上げ、枠 1 が EX スキル、枠 2 がそれ以外のスキル、枠 3 が固有武器、枠 4 が愛用品です。中身は DB/RecipeIngredientExcelTable.json の CostAmount（クレジット）と IngredientId / IngredientAmount（素材）です。

ノーマル・パッシブ・サブの 3 つはどれも枠 2 の同じ表を使います。ゲームの中でも、この 3 つは同じ素材と同じクレジットで上がります。

スキルの ◎ と「キリのいい Lv まで」はデータではなく攻略サイトの記載です。ブルアカ Wiki「スキル」に「EXスキルはLv3とLv5になった際に数値が大きく伸びる」「EX以外のスキルはLv4、Lv7、Lv10になった際に数値が大きく伸びる」「最大まで育成する余裕がない場合は数値が大きく上がるキリのいいLvを目指すと効率がいい」とあります。ゲームエイト「スキル上げのおすすめキャラ」にも「EXはレベル3と5、その他のノーマル・パッシブ・サブスキルはレベル4・7・10に到達した際に、スキルの倍率が大きく上がります」とあり、2 サイトで一致します（2026 年 8 月 31 日に確認）。ボタンはこれに沿って Lv90・EX Lv5・ほかのスキル Lv7 を入れます。 Lv10 まで行かないのは、その 1 段だけで秘伝ノート 1 冊と 400 万クレジットが要るからです。どの生徒でもこれが正解、という話ではありません。手で書き換えてください。

固有武器は★4 までです。Excel/CharacterWeaponExcelTable.json の Unlock は 224 本すべて [true, true, true, false, false] で★3 に見えますが、こちらは止まっている写しです。 DB/CharacterWeaponExcelTable.json は 275 本あって、どれも [true, true, true, true, false] です。日本で開いている段は SchaleDB の config.json の Regions[Jp].WeaponMaxLevel（60 ＝★4）から取っています。★3→★4 の神名文字だけ、レシピの値が「1 個」の仮置きのままです—— クレジットは 2000000 と実数が入っているので、個数だけ ゲームエイトの200 個で補っています（星上げの区画と同じ値）。 2026-08-31 まで★3 で止めていました。

レベルの必要経験値は DB/CharacterLevelExcelTable.json そのままです。 Lv1 から Lv90 までの合計は —。レポートの経験値は初級 50 ／ 中級 500 ／ 上級 2,000 ／ 最上級 10,000 で、これもデータの値です。

レベル上げのクレジットは 1 経験値につき 7 で計算しています。この 7 は Excel/ConstCommonExcelTable.json の CharacterLvUpCoefficient です。ブルアカ Wiki「経験値表」の「育成にはレポートとクレジットが必要で、1EXPあたり7クレジットのコストが掛かる」という記載によります。 Lv1 から Lv90 まででちょうど — になり、同ページの「約875万」と合います。

愛用品を持っている生徒は — 人です。持っていない生徒では、その行を選べません。固有武器も同じで、持っていない生徒では選べません。

装備は 3 部位とも、深掘り側の 2 本と同じ数え方です。Tier 上げの設計図とクレジットは SchaleDB の装備の Recipe と RecipeCost（装備の計算機の「設計図を集める」と同じ）。 レベル上げは DB/EquipmentLevelExcelTable.json の TotalExp を Tier ごとに Lv1 から数え、1 EXP につき EquipmentLvUpCoefficient（4）クレジット（装備の計算機の「強化珠」と同じ）。 強化珠の経験値は、レポートの経験値とは別に出しています。食べさせるものが違うからです。 2026-09-26 まで装備は数えていませんでした。

固有武器の Lv は、2026-09-26 に廃止した固有武器の強化計算機から移しました。経験値は DB/CharacterWeaponLevelExcelTable.json の TotalExp。この列は「次のレベルまで」の累計で、行 Level: 49 の 26280 が Lv1 → Lv50 のぶんです（ゲームエイト「経験値テーブル一覧」の 26,280 と一致）。 ★ごとの Lv 上限は DB/CharacterWeaponExcelTable.json の MaxLevel（30 / 40 / 50 / 60 / 70）を日本の上限で押さえたもの。 1.5 倍になる系統は DB/CharacterWeaponExpBonusExcelTable.json（武器種 11 種、値は 15000 か 10000）、武器パーツの経験値は SchaleDB の equipment の LevelUpFeedExp です。 レベル上げのクレジットは数えていません。WeaponLvUpCoefficient という値はありますが、実機で突き合わせていないためです。

絆ランクの贈り物はこのツールでは数えていません。絆ランク計算機にあります。

出典 — SchaleDB（生徒・素材の名前とアイコン）、 electricgoat/ba-data（レシピ・経験値表・装備と固有武器の経験値表・パーツの倍率）、SchaleDB config.json（日本で開いている固有武器の段）、ゲームエイト（★3→★4 の神名文字 200 個）。取得は —。

数字の出どころ

要る神名文字とクレジットは、ゲームのレシピをそのまま読んでいます。推測はありません。

  • DB/CharacterTranscendenceExcelTable.json — 生徒ごとに RecipeId が 4 つ（★1→2、2→3、3→4、4→5）並んでいます
  • その Id を DB/RecipeExcelTable.json → DB/RecipeIngredientExcelTable.json と辿ると、 CostAmount（クレジット）と IngredientId（その子の神名文字）と IngredientAmount（個数）が出ます
  • — 人ぶんを 1 人ずつ数えて、4 段とも全員同じ値であることを確かめています。 神名文字は 30 / 80 / 100 / 120 で合計 330 個、クレジットは 10,000 / 40,000 / 200,000 / 1,000,000 で合計 1,250,000 です。 1 人でも違う値が出たら、データを作る側で止まるようにしてあります。
  • 絆ランクの上限は同じ表の MaxFavorLevel。★1 から順に 10 / 10 / 20 / 30 / 100 で、★3 で 20、★4 で 30、★5 で 100 まで開きます。★4 のぶんは 20 から 30 に上がりました（DB/ の 817 行のうち 810 行がこの並び。止まっている Excel/ 側はまだ 20 です）

★5 のあとは「限界解放」です。★の上げ方を神秘解放、固有武器の上げ方を限界解放と呼び分けます （ブルアカ攻略 Wiki の「神秘解放/限界解放」）。 ★5 になると固有武器が使えるようになり、その状態が固有1です。そこから固有2・固有3・固有4 と続きます。

  • DB/CharacterWeaponExcelTable.json の RecipeId が段の並びです。 ★のときと同じように RecipeExcelTable → RecipeIngredientExcelTable と辿ります。 神名文字は 120 / 180 / 200、クレジットは 1,000,000 / 1,500,000 / 2,000,000 です
  • 固有武器のレベル上限は同じ表の MaxLevel。30 / 40 / 50 / 60 / 70 で、 固有1 で Lv30、固有4 で Lv60 です（70 の段＝固有5 は日本ではまだ出ていません）
  • 覚えるものも同じ表から読んでいます。LearnSkillSlot の 2 番目が Passive01 なので 固有2 でパッシブスキル＋、StatType の 3 番目が 〇〇BattleAdaptation_Base なので 固有3 で地形適性です。上がり幅は生徒ごとに違います—— ＋1 段が — 人、＋2 段が — 人で、 StatValue をその子ぶん読んでいます

固有3→固有4 の神名文字 200 個も、いまはゲームのデータに入っています。 DB/RecipeIngredientExcelTable.json の IngredientAmount が 200、CostAmount が 2,000,000 です。 止まっている Excel/ 側では 1 の仮置きのままで、 2026-08-31 まではここだけ game8 の「固有武器★4の解放必要素材」の 200 個で補っていました。データ側の値と、外から取っていた値は同じでした。

固有4 で増えるものもデータに入っています（DB/CharacterWeaponExcelTable.json の StatType / StatValue の 4 番目。Excel/ 側は None のままです）。 ストライカーは Enhance〇〇Rate_Base が 1000＝自分の攻撃属性の特効 ＋10%で — 人、 スペシャルは MaxCostIncrease_Base が 5000＝コスト上限 ＋0.5で — 人。 — 人ぜんぶが、その子の SquadType と BulletType どおりでした （1 人でも外れたらデータを作る側で止まります）。ブルアカ攻略 Wiki の「限界解放 星3→星4」の欄 （ST:〇〇特効加算+10%、SP:最大コスト0.5増加）とも一致します。

データに星上げのレシピが入っていない生徒は、この一覧に出しません。 IngredientId が「神名のカケラ」（Id 23）を 999 個という仮置きの行になっている生徒と、 レシピそのものが空の生徒がいます。実装が追いついていないだけなので、ゲーム側では上げられます。 このツールは読めた — 人ぶんだけを出しています。

カケラの値段もゲームのデータから読んでいます。

  • DB/GoodsExcelTable.json の、ConsumeParcelId が [23]（神名のカケラ）で ParcelId がその子の神名文字の行。ConsumeExtraStep が —、 ConsumeExtraAmount が — で、その子の文字を今までに買った数で 1〜20 個目は 1 個、21〜40 個目は 2 個……と上がり、並びの最後（81 個目から 5 個）がそのあとも続きます
  • 1 人ぶんの上限は DB/ShopExcelTable.json の CategoryType SecretStone の PurchaseCountLimit（— 個）。値段と上限が 1 人でも違ったら、データを作る側で止まります
  • ブルアカ攻略 Wiki の早見表（★1→★5 が 330 文字・1,450 カケラ、★1→固有4 が 830 文字・3,950 カケラ、 ★3→★5 が 220 文字・900 カケラ、固有2→固有4 が 380 文字・1,700 カケラ）と一致します

出典 — electricgoat/ba-data（レシピ・覚えるもの・カケラの値段）、 SchaleDB（生徒と道具の名前、顔の絵、日本の上限）、 ブルアカ攻略 Wiki（呼び名と早見表の答え合わせ）、 game8（固有3→4 の神名文字。いまはデータ側にも入っていて、値が一致しています）。取得は —。

数字の出どころ

要る量はゲームのレシピをそのまま読んでいます。推測した数字はありません。

  • 段ごとの中身は SchaleDB の config.json の PotentialMaterial（25 要素）。 この配列の [i] は「i 段目に到達するぶん」ではなく「i 段目から i+1 段目へ上げるぶん」です。 到達段で引くと 5・10・15・20 段目の境目が全部 1 段ずれます
  • 裏取りとして、DB/CharacterPotentialStatExcelTable.json の RecipeId を DB/RecipeExcelTable.json → DB/RecipeIngredientExcelTable.json と辿り、 — 手順すべてを 1 つずつ突き合わせています。 クレジット・オーパーツの個数・WB の冊数が 1 か所でも食い違ったら、データを作る側で止まります
  • どのオーパーツを使うかは DB/CharacterPotentialExcelTable.json の PotentialStatGroupId を 100 で割った値。 SchaleDB 側の PotentialMaterial と — 人全員で一致しました
  • 枠は PotentialStatGroupId の下 2 桁で決まります。10 が最大 HP、 20 が攻撃力、30 が治癒力。WB もそれぞれ 応用体育 / 応用射撃 / 応用衛生 に固定です
  • 「この枠は使わない」の印は同じ表の IsUnnecessaryStat。ゲームのデータが持っている印で、 こちらで判断したものではありません（治癒力に立っている生徒が — 人います）
  • 段の上限 25 と、開放に Lv90 が要ることは Excel/ConstCommonExcelTable.json の PotentialBonusStatMaxLevelMaxHP ほかと PotentialOpenConditionCharacterLevel
  • 伸び幅は StatBonusRate。1 段あたり 20 で、10000 分率なので 0.2%、25 段で 5% です。 25 段ぶん全部を数えて、段 × 20 になっていることを確かめています。 掛け方は SchaleDB 本体の計算に合わせました —— あちらの JavaScript が Math.round(基礎値(Lv) × 段数 × 0.002) としていて、 0.002 は 20 / 10000 と同じです （schaledb.com の assets/StudentListModal-*.js。2026-08-30 に読みました）
  • 基礎値の出し方も同じところから。Lv1 と Lv100 の 2 点を 基礎値 = round(Lv1 + (Lv100 − Lv1) × (Lv − 1) / 99) で結んでいます。 ★の倍率は掛けません。SchaleDB も潜在能力ぶんは★を掛ける前の値から数えています

オーパーツと応用 WB の入手先は出していません。ステージのドロップをぜんぶ当たりましたが、 「◯◯の欠片」も応用 WB も 1 本も落ちてきませんでした。裏が取れないので書かないことにしています。 手持ちの数は自分で入れる形にしました。

出典 — electricgoat/ba-data（レシピ・枠・上限）、 SchaleDB（段ごとの中身、生徒と道具の名前、顔の絵、伸びの掛け方）。取得は —。
