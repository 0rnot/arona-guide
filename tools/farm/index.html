数字の出どころ

落ちる個数はゲームのデータをそのまま読んでいます。周回してドロップを数えた値ではありません。

  • ステージと報酬は SchaleDB の data/jp/stages.min.json。任務・指名手配・特別依頼・学園交流会の 320 本のうち、素材が落ちる — 本を載せています
  • 1 周あたりの期待個数は 個数 × Chance。AmountMin / AmountMax があるときはその平均、Chance が無ければ 1.0 です。 Amount と AmountMin/Max は掛け算です —— SchaleDB 本体の実装（assets/ItemView-*.js）も (Amount??1) * (AmountMin??1) と掛けています
  • 初回クリア報酬（FirstClear）と 3 つ星報酬（ThreeStar）は数えていません。 周回では出ないからです
  • 箱（GachaGroup）の中身は SchaleDB の data/groups.min.json。中身ごとに Chance が入っているので、 期待個数は 箱の期待個数 × 中身の Chance × 中身の個数です。 ba-data の GachaElementExcelTable は使っていません。 あちらは 2025-05-07 で止まっていて、たとえば箱 10314 が 「百鬼夜行・トリニティ・アリウスの 3 種で各 1/3」になっています。 実際はオデュッセイアが加わった 4 種で各 0.25 で、使うと期待個数が 1.33 倍に膨らみます。 ステージが使う 100 個の箱を 1 つずつ突き合わせて、中身が同じ 83 個では 確率が 0.002 以内で一致し、残り 16 個は SchaleDB 側にだけ新しい学校が 入っていることを確かめました（2026-08-30）
  • 箱 500000 / 500001 / 500100 は数えていません。 groups.min.json の中身が全部 "Chance": 0 の空の箱で、 SchaleDB 本体も名指しで外しています（assets/ItemView-*.js の g=[5e5,500001,500100]）
  • 入場料は EntryCost。通貨 5 が AP、22 が指名手配券、23 が学園交流会チケットで、 出てくるのはこの 3 つだけです（4 つ目が出たらデータを作る側で止まります）。 学園交流会はチケットと AP の 2 本立てなので、券あたりと AP を別々に出しています
  • 名前の無いステージ（指名手配・特別依頼・学園交流会の 70 本）は data/jp/localization.min.json の StageTitle に番号を差し込んで作っています。 "ChaserA": "ハイウェイ{0}" のような形です。 FindGift は「贈り物」ではなくクレジット回収で、これも同じところの StageType が正本です
  • 数えている素材は — 種、 （素材, ステージ）の組は — 件。 アイテムを落とすステージは — 本で、 これを下回ったらデータを作る側で止まります

イベントステージは入っていません。stages.min.json には 任務・指名手配・特別依頼・学園交流会の 320 本しか無く、イベントの周回効率は出せません。 強化珠もこの一覧には出ません —— 320 本の報酬を全部当たって、 Equipment の Id 1〜4（初級〜最上級強化珠）は 1 件も出てきませんでした。

ドロップ 2 倍・3 倍は、1 周あたりの期待個数をそのまま倍にしています。 倍率が報酬のどの行に掛かるかまではデータに書かれていないので、そこは確かめられていません。
