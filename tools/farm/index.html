数字の出どころ

落ちる個数はゲームのデータをそのまま読んでいます。周回してドロップを数えた値ではありません。

  • ステージと報酬は SchaleDB の data/jp/stages.min.json。任務・指名手配・拠点防衛・学園交流会のうち、 素材が落ちる — 本を載せています
  • 指名手配だけは ba-data から直接読んでいます。 9/23 の改修（エリアが 5 つに・ドロップ率の上昇・どのエリアもステージ07 から挑戦可能）が SchaleDB にまだ入っていないためです。WeekDungeonExcelTable と WeekDungeonRewardExcelTable で、確率は 1/10000 単位、確率 0 の行は画面に出すだけで落ちません。 「使うとすぐ開く箱」のアイテム（例 30022 → 箱 10322、初級戦術教育BD のゲヘナかハイランダー）は 箱に開いて数えています。9/9 版のデータで同じ組み方をすると、SchaleDB の 30 本と行ごとに一致しました。 神名文字 20 種の箱（10600）も 1 周 10% で落ちるので、1 種あたり 0.005 個として載せています
  • 1 周あたりの期待個数は 個数 × Chance。AmountMin / AmountMax があるときはその平均、Chance が無ければ 1.0 です。 Amount と AmountMin/Max は掛け算です —— SchaleDB 本体の実装（assets/ItemView-*.js）も (Amount??1) * (AmountMin??1) と掛けています
  • 初回クリア報酬（FirstClear）と 3 つ星報酬（ThreeStar）は数えていません。 周回では出ないからです
  • 箱（GachaGroup）の中身は SchaleDB の data/groups.min.json。中身ごとに Chance が入っているので、 期待個数は 箱の期待個数 × 中身の Chance × 中身の個数です。 ba-data の GachaElementExcelTable は、SchaleDB にまだ無い 9/23 の指名手配の箱にだけ使っています （そのときは画面に出る素材の顔ぶれと突き合わせ、食い違えばデータを作る側で止まります）。 あちらは古い箱で学校が欠けていて、たとえば箱 10314 が 「百鬼夜行・トリニティ・アリウスの 3 種で各 1/3」になっています。 実際はオデュッセイアが加わった 4 種で各 0.25 で、使うと期待個数が 1.33 倍に膨らみます。 ステージが使う 100 個の箱を 1 つずつ突き合わせて、中身が同じ 83 個では 確率が 0.002 以内で一致し、残り 16 個は SchaleDB 側にだけ新しい学校が 入っていることを確かめました（2026-08-30）
  • 箱 500000 / 500001 / 500100 は数えていません。 groups.min.json の中身が全部 "Chance": 0 の空の箱で、 SchaleDB 本体も名指しで外しています（assets/ItemView-*.js の g=[5e5,500001,500100]）
  • 入場料は EntryCost。通貨 5 が AP、22 が指名手配券、23 が学園交流会チケットで、 出てくるのはこの 3 つだけです（4 つ目が出たらデータを作る側で止まります）。 学園交流会はチケットと AP の 2 本立てなので、券あたりと AP を別々に出しています
  • 名前の無いステージ（指名手配 50 本・拠点防衛 14 本・学園交流会 12 本の 76 本）は data/jp/localization.min.json の StageTitle に番号を差し込んで作っています。 "ChaserA": "ハイウェイ{0}" のような形です。 FindGift（スランピア広場）は「贈り物」ではなくクレジット回収で、 素材を落とさないのでこの表には 1 本も出てきません（StageType が正本）
  • 数えている素材は — 種、 （素材, ステージ）の組は — 件。 アイテムを落とすステージは — 本で、 これを下回ったらデータを作る側で止まります

イベントステージは入っていません。stages.min.json には 任務・指名手配・拠点防衛・学園交流会のぶんしか無く、イベントの周回効率は出せません。 強化珠もこの一覧には出ません —— その報酬を全部当たって、 Equipment の Id 1〜4（初級〜最上級強化珠）は 1 件も出てきませんでした。

ドロップ 2 倍・3 倍は、1 周あたりの期待個数をそのまま倍にしています。 倍率が報酬のどの行に掛かるかまではデータに書かれていないので、そこは確かめられていません。

出典 — SchaleDB、指名手配は ba-data。 期待個数の出し方も、あちらの assets/ItemView-*.js に合わせています。 取得は —。

数字の出どころ

枠の色はレアリティです。欠片が N、壊れたが R、摩耗したが SR、完全なが SSR で、 これは SchaleDB の data/jp/items.min.json の Rarity をそのまま読んでいます。 色そのものも SchaleDB の --col-bg-item-n / -r / -sr / -ssr と同じ値です （明るい配色のとき rgb(189,197,208) / rgb(144,186,236) / rgb(214,173,129) / rgb(168,138,236)、暗い配色のとき rgb(140,147,158) / rgb(101,141,191) / rgb(168,125,81) / rgb(122,91,190)）。

個数は上で選んだ範囲のものです。既定は最大まで—— EX スキルを Lv1 → Lv5、ノーマル・パッシブ・サブをそれぞれ Lv1 → Lv10 にしたときに使う数を足しています。 EX 以外の 3 つは同じ表を使うので、1 つぶんの 3 倍です。1 人ずつ範囲を変えたいときは生徒の育成計算機で出せます。

素材そのものは SchaleDB の data/jp/students.min.json の SkillExMaterial / SkillMaterial です。種類の分け方はアイコンの名前で決めています—— item_icon_material_exskill_* が戦術教育 BD、item_icon_skillbook_* が技術ノート、それ以外の item_icon_material_* がオーパーツです（Category はどれも Material で区別が付きません）。

Lv9 → Lv10 の秘伝ノートは、ここには出していません。誰でも 1 冊で同じで、素材から生徒を絞る役に立たないためです。

出典 — SchaleDB（生徒・素材と必要数）、electricgoat/ba-data（レシピ）。取得は —。
