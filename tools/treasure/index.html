おすすめのマス

上から順に、備品に当たる確率が高いマスです。「当たる備品の大きさ」は、そこに何かあったときそれが何マスの備品かの期待値で、大きいものほど見つけたときの手がかりが増えます。

備品の型

イベントごとに名前も大きさも変わります。ゲーム内の表示に合わせて、名前・よこ・たて・個数を書き換えてください。

この周の中身を入れる押すと下の 3 つが入れ替わり、盤面も白紙に戻ります

入力に矛盾があると「あり得る置き方 0 通り」になります。個数や印を見直してください。数え上げが 0 になった時点で確率は出せません。

計算はぜんぶこのページの中でやっています。入れた内容が外へ送られることはありません。

数字の出どころと、計算のしくみ

備品の名前・大きさ・個数と、当てたときにもらえるものは、イベントのデータそのままです。 DB/EventContentTreasureRoundExcelTable.json の RewardID から DB/EventContentTreasureRewardExcelTable.json を引き、 CellUnderImageWidth / CellUnderImageHeight（よこ・たて）と RewardParcelType / RewardParcelId / RewardParcelAmount（中身）を読んでいます。 名前は Item が SchaleDB の items.min.json、Equipment が equipment.min.json です。 どちらにも載っていない Id が 3 つ（85363・85373・85403）あり、そこは 「？（Item 85363）」のように Id ごと出しています。伏せると、何が抜けたのか分からなくなるからです。

開いた直後は、選んだイベントの 1 周目が入っています。周を押せば入れ替わります。 名前・よこ・たて・個数はどれも手で書き換えられるので、データが追いついていない回でも使えます。

盤は 9 × 5 の 45 マス。備品は重ならずに置かれていて、種類ごとの個数は決まっています。ここから「条件に合う置き方」をすべて数え上げ、そのうち何通りでそのマスが備品に覆われているかを割ったものが確率です。近似やサンプリングは使っていません。

備品は 90 度回して置かれることがあります。3×1 の備品なら、横 3 マスだけでなく縦 3 マスの向きもあり得るということです。これを数に入れているので、見た目より確率が下がることがあります。たとえば横 3 マスの備品を左端の 2 マスぶん見つけたとき、「その右隣も必ず同じ備品」とは限りません。縦向きの別の備品が 2 つ並んでいることもあるからです。 terry-u16 の在庫管理計算機も、置き方を「回した／回していない」の 2 通りで数えています。

置いてある前提。置き方はあり得る全通りから一様に選ばれていて、開ける前に決まっており、あとから変わらない。この 3 つを仮定しています。決まった型（絶対に出ない配置）があると、ここで出す数字はずれます。

数え上げのやり方。盤を左の列から順に見ていき、各行について「いまの列から先、あと何マスぶん埋まっているか」だけを持ち歩きます。前向きの数え上げと後ろ向きの数え上げを掛け合わせると、1 マスごとの確率が厳密に出ます。1 周目（タツノオトシゴ 4・海藻 3・ウニ 1）なら、置き方は 175,761,438 通りあります。

備品の大きさと個数は、ゲームのデータから毎日作り直しています。 DB/EventContentTreasureRoundExcelTable.json の RewardID と RewardAmount が周ごとの中身、 DB/EventContentTreasureRewardExcelTable.json の CellUnderImageWidth / CellUnderImageHeight が備品の大きさ、 TreasureRoundSize が盤の大きさです。備品の名前は LocalizeCodeID を XXHash32（seed 0）にかけて DB/LocalizeExcelTable.json の Key と突き合わせて引いています。新しいイベントが来れば、翌日には選べるようになります。

2026-08-30 まではここに DIVE into OCEAN！の 13 周ぶんを手で書いていました。 terry-u16/schale-inventory-management（MIT ライセンス）の src/components/MainArea.tsx から写したものです。データから作り直した値と 1 つ残らず一致しました。「周目」という呼び方も、ゲーム側の列名 TreasureRound と、同じリポジトリの日本語ロケール（1周目〜13周目以降）に合わせています。解き方は同じ考え方の DP ですが、こちらは通り数がいくつでも厳密な値を出します。

過去のイベントもぜんぶ選べます。在庫管理のミニゲームは名前と大きさを変えて何度も来ていて、今のところ 12 回ぶんが入っています。載っていないものでも、備品は毎回 3 種類なので、上の欄を書き換えればそのまま使えます。
