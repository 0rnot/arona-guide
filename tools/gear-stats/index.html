数字の出どころ

装備のステータスは equipment.min.json の StatType / StatValue です。 StatValue は ［Lv1 のときの値, その段の最大 Lv のときの値］で、最大 Lv は MaxLevel（T1 は 10、T10 は 70）です。末尾が _Coefficient のものと、名前が Rate・Ratio で終わるものは 10000 分率なので 100 で割って % にしています。それ以外は実数です。

「1 段上げると」は、その段の最大値から 1 つ下の段の最大値を引いたものです。 Lv を上げきった装備どうしを比べています。作るのに要る素材とクレジットは Recipe / RecipeCost で、周回して集める話は装備設計図の周回計算機にあります。

設計図と万能設計図は同じ表に混ざっていますが、ステータスを持たないので外しています。

愛用品は Gear です。— 人が持っています。 StatValue には数字が 2 つ入っていますが、 66 人ぶんを全部見たところ、どの子も 2 つとも同じ値でしたので 1 つだけ出しています。愛用品 T2 で効果がどう変わるかは、このデータからは分かりません。持っていない生徒はここに出ません。

固有武器は、固有の段（限界解放）でレベル上限が変わります。 Excel/CharacterWeaponExcelTable.json の MaxLevel が 30 / 40 / 50 / 60 / 70 で、固有1 が Lv30、固有4 が Lv60 です。 224 人ぶんを数えて全員同じであることを確かめています。 70 の段（固有5）は日本ではまだ開いていません—— SchaleDB の config.json の Regions の Jp が "WeaponMaxLevel": 60 だからです。SchaleDB 本体も WeaponStarGrade を WeaponMaxLevel / 10 - 2 で頭打ちにしています。

段ごとの攻撃力・最大 HP・治癒力は、SchaleDB と同じ式で出しています。 データに入っているのは AttackPower1 / AttackPower100 のような Lv1 と Lv100 の 2 点だけで、あいだは Math.round(Lv1 + (Lv100 − Lv1) × (Lv − 1) ÷ 99) で埋めます （schaledb.com の assets/index-*.js の mg() と g$()。 Standard・LateBloom・Premature の 3 つはどれも直線で、 段が付くのは TimeAttack だけ。固有武器にその型の子はいません）。 裏取り: 274 人ぶん 680 組で、この式が Lv1 と Lv100 の値をぴったり返すことを確かめました。 以前このツールは「Lv1 → Lv100」と出していましたが、Lv100 には届きません。

固有武器の「地形適性 ＋1」は AdaptationType と AdaptationValue です。これが乗るのは固有3 からで、 SchaleDB 本体も WeaponStarGrade >= 3 のときだけ足しています。 伸び幅は生徒ごとに違い、＋1 が 247 人、＋2 が 27 人です。

固有2 と固有4 で増えるものは、少しだけ出どころが違います。 固有2 の「パッシブスキル＋」は LearnSkillSlot の 2 番目が Passive01 であることから。固有4 のぶんはゲームのデータに入っていません—— StatType の 4 番目は None のままです。 ストライカーは特効 ＋10%、スペシャルはコスト上限 ＋0.5 で、これは game8 と、 ブルアカ攻略 Wiki の「限界解放 星3→星4」の欄（ST:〇〇特効加算+10%、SP:最大コスト0.5増加）が一致しています。 どちらを出すかは SquadType で切り替えています。

出典 — SchaleDB（装備・愛用品・固有武器・日本の上限）、 electricgoat/ba-data（固有武器のレベル上限）、 game8 と ブルアカ攻略 Wiki（固有4 の効果）。取得は —。
