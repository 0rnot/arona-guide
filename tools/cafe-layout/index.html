カフェの家具配置

カフェの床と壁に家具を並べて、置ける・置けないと快適度の合計を確かめます。公式の家具テンプレート 20 個をそのまま読み込めます。

AronaBotの使い方/ツール/カフェの家具配置

床と壁に並べる

右で家具を選んで、マス目を押すと置けます。カーソルのマスが家具の左上になります。すでに家具があるところには置けません。床の装飾（カーペット）だけは、家具の下に敷けます。

公式のテンプレートを読み込む

ゲームが持っている家具テンプレート 20 個です。押すと、いま並べているものをすべて置き換えてそのまま盤に載せます。この 20 個は 1 マスもはみ出さず、重なりもありません。それが、床 20×20・壁 20×7 という広さの裏取りになっています。

数字の出どころ

床と壁の広さは、2 つの別々のところから同じ答えが出ました。ゲームのデータに「部屋の広さ」という欄はありませんが、次の 2 つで確かめられます。

  • 1 枚で部屋いっぱいに敷く家具の大きさ。 SchaleDB の furniture で SubCategory が Floor（床材）の 26 個のうち 8 個が "Size": [20, 20]、 Wallpaper（壁紙）の 26 個のうち 2 個が "Size": [20, 7] です。 — 1,091 個の家具のうち、縦にも横にも 20 を超えるものは 1 つもありません。
  • 公式の家具テンプレート 20 個を、その枠に置き直せること。 Excel/FurnitureTemplateElementExcelTable.json の 1,299 行には、 テンプレートごとに家具の PositionX / PositionY / Rotation が入っています。座標は家具の中心で、 幅が奇数のときだけ .5 が付きます （マス目に乗る 1,239 行のうち 1,231 行で成り立ちました。 外れる 8 行はいちばん近いマスへ丸めていますが、 丸めてもはみ出し 0・重なり 0 のままです）。 左上のマスを round(座標 − 大きさ ÷ 2) で出すと、 5,147 マスが 1 マスもはみ出さず、重なりも 0 でした。 1 つでもはみ出すか重なったら、データを作る側で止まります。
  • 床の装飾（カーペット）だけは重ねてよいことも、そこから分かります。 カーペットを検査に入れると重なりが 459 マス出ますが、外すと 0 になります。 つまり公式のテンプレートはカーペットの上に家具を置いています
  • どの家具がどの面に行くかは、同じ表の Location 欄 （Floor / WallLeft / WallRight）から決めました。 ベッド・椅子・クローゼット・床の装飾・家電・小物・テーブルは 1,037 行すべてが Floor、壁の装飾は 202 行すべてが壁で、混ざった行は 1 つもありません。 床材・壁紙・背景はどのテンプレートにもちょうど 1 つずつ入っていたので、 この画面でも 1 つだけ選ぶ形にしています

快適度の出し方。

  • 家具そのものの快適度は furniture の ComfortBonus。 20 / 50 / 120 / 180 / 350 / 500 の 6 段階しかありません
  • セットボーナスの段は Excel/FurnitureGroupExcelTable.json の RequiredFurnitureCount = [2, 3, 5, 7] と ComfortBonus = [100, 200, 450, 750]。 20 セットすべて同じ値でした。同時に効くセット数は Excel/ConstCommonExcelTable.json の CafeSetGroupApplyCount = 3
  • この 4 つは足し上がります。データだけでは「置き換わる」のか 「足し上がる」のか決められないので、外の表と突き合わせました。 神ゲー攻略が 「同シリーズ配置数 2個 / 3個 / 5個 / 7個」に対して 「ボーナス値 100 / 200 / 450 / 750」「上昇する快適度 100 / 300 / 750 / 1500」という 2 列の表を出していて、右の列が左の列の積み上げになっています。 ゲームエイトの 表も「2個 100 / 3個 200 / 5個 450 / 7個 750 / 合計 1500」で、 1 セットの上限が 1,500 という点で 2 つが一致しました。 この画面はその積み上げ（7 個で ＋1,500）で計算しています
  • 確かめられていないこと が 2 つあります。 1 つは同じ家具を 2 個置いたとき、セットの数え方が「個数」なのか「種類」なのか。 神ゲー攻略は「同じシリーズの家具が配置されている数に応じて」と書き、 ゲームエイト側は「7種を置くと」と書いていて、言い方が割れています。 この画面は個数で数え、表に種類の数も並べています。 2 つの数が食い違ったときは、表の下に注意書きが出ます。 もう 1 つは効く 3 セットの選び方で、 この画面はボーナスが大きい順に 3 つとしています
  • 快適度の上限は Excel/CafeRankExcelTable.json の ComfortMax。1,000 から 500 きざみで 5,500 までで、 これが並んでいなければデータを作る側で止まります

参考にしたもの。この画面は kur-3dcg さんの「家具シミュレーションツール」 （GitHub）を 先に読んでから作りました。借りたのは考え方だけで、コードは 1 行も写していません。 向こうは 20×20 のマス目・家具は長方形・重ねて置けない・R キーで 90 度ずつ回転・ 置く前に「置ける／置けない」を見せる・localStorage に残すという骨格で、 ここもその骨格に合わせています。ただし向こうは家具の名前と大きさを手で入力する形で、 ブルアカのデータは読み込んでいません（読み込んでいるのは Pixi.js だけ）。 こちらは家具・大きさ・快適度・セット・公式テンプレートをすべてゲームのデータから引いています。 見た目はクォータービューではなく真上からにしました。斜めに描くと横幅が 1,280px 必要で、スマホで横にはみ出すためです。 向こうのリポジトリに LICENSE ファイルはありません（README には 「このツールは教育・学習目的で作成されています」とだけあります）。 そのぶんコードは写さず、考え方とデータの出どころだけを借りています。 tools/cost-timeline/ でも同じ方の characters_st.json を参考にしています

出していないもの。 1 号店と 2 号店で床の形が違うかどうかは分かりません。 Excel/CafeInfoExcelTable.json は 2 行しかなく、持っているのは IsDefault と開放条件の名前だけで、広さも形も入っていません。 公式テンプレートにも「どちらの店用か」という欄がありません。 この画面は両方を 20×20 として扱っています。実際の 2 号店で合わない場合があります。 床の形が長方形でない（柱や段差でマスが欠けている）可能性も否定できません。 テンプレートが使っていないマスがあっても、それが「置けないマス」なのか 「たまたま置いていないマス」なのかはデータから区別できないので、 欠けは作っていません。 トロフィー 96 個とその他 8 個は 盤に載せていません。この 2 種類は公式テンプレート 20 個に 1 度も出てこないので、 床なのか壁なのかが確かめられませんでした。快適度の合計にも入れていません。 家具を「持っているかどうか」も見ていません。全部持っている前提の画面です。
